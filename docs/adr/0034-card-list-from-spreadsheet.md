# 0034: Card lists from spreadsheets are read in the browser

## Status

Accepted.

## Context

Players keep their collection in Excel or as CSV and asked to bring it into the
inventory instead of typing it again. The quick capture already turns a list of
lines into reviewed, saved cards (ADR 0003, ADR 0010); the missing piece is
getting from a spreadsheet to those lines.

The pieces that decide the design: an `.xlsx` is a zip of XML written by Excel,
LibreOffice and many scripts, a spreadsheet is untrusted input, and a real
collection file is not always a clean table (a dashboard sheet first, the card
list on another sheet, a quantity column called "Anzahl in aktueller Planung").

## Decision

### Read in the browser, send lines

The file never goes to the server for this. `app/utils/spreadsheet-list.ts`
reads it into the lines quick capture already takes (`3x Dark Magician (SDY-006)`)
and the existing `POST /api/inventory/entry/suggest` matches them against the
catalog. That keeps the server free of a spreadsheet parser, and the review
table, the 50-line request cap and "nothing is written before it is confirmed"
stay exactly as they are.

- `.xlsx` / `.xlsm`: unzipped with `fflate` (small, no dependencies) and read by
  a small parser of our own: shared and inline strings, numbers, sparse cells,
  hidden sheets skipped, names matched without regard to case or namespace prefix.
  Only the workbook, its relationships, the shared strings and the worksheets are
  unpacked, and no part may be larger than 50 MB uncompressed.
- `.csv` / `.tsv` / `.txt` / `.ydk`: parsed as text. A delimiter (`;`, tab, `,`)
  counts only when nearly every line has the same number of fields, so a plain
  list with a comma in some card names ("Brecher, Magischer Krieger") stays a list.
- Old `.xls` and `.ods` are refused with a hint to save as `.xlsx` / `.csv`,
  rather than adding a parser for each. Files over 5 MB and lists over 5,000
  lines are refused or cut, and the page says so.

### Finding the columns

A header row within the first five rows names the columns: a card name
("Name", "Kartenname", "Karte", "Card …"), an optional quantity ("Menge",
"Anzahl …", "Qty", "Bestand" …) and an optional set code (used only when the
cells look like set codes, so a column of set *names* is ignored). "Karten" and
"Cards" are deliberately not name headers: as a header they usually mean a
count. Without a header, a column of small whole numbers is the quantity and the
most text-like remaining column the name. A name that is a bare number of up to
four digits is a count, not a card, and is skipped; an empty or zero quantity
skips the row. A passcode (five to ten digits) is a valid name.

### Several sheets

Every visible sheet is read. Sheets with a card-name header are the candidates;
sheets without one only count when none has one, so a dashboard of numbers is
not offered. With one candidate it is read straight away; with several the page
asks which sheet to read ("Decklisten · 151 Zeilen", "Inventar · 110 Zeilen")
and reads nothing before the choice. The row count tells the user which is which,
and picking the wrong sheet costs nothing because nothing is saved yet.

### Long lists

The review table holds 200 rows and a request 50 lines. A long file goes in
50 lines at a time, up to what is free in the table; the rest waits ("Nächste
Zeilen laden") until the first rows are saved. Nothing is dropped silently.

### Where it appears

The quick capture has "Excel- oder CSV-Datei einlesen". The inventory files page
(ADR 0033) has "Karten importieren" on every `.xlsx` / `.csv` / text file: it
reads the stored file the same way and opens the quick capture with the result.

## Consequences

- One small client-side dependency (`fflate`) and about 350 lines of our own
  parsing, tested against hand-built workbooks and one real Excel file.
- Matching is as good as the catalog match: on a real 112-line collection sheet
  94 lines were certain, 15 uncertain and 3 unmatched, and the review table is
  where those are settled.
- Formulas are read as their cached values, as Excel stores them; a workbook
  never opened in Excel after being generated by a script may have none.
- Only the first 5,000 lines of a sheet are read; a collection bigger than that
  needs splitting into several files.
